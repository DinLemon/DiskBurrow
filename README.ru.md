## Установка

1. Скачайте `DiskBurrow-0.2.2-win-x64.zip` и `.sha256` из Releases. Получите SHA-256 командой `Get-FileHash .\DiskBurrow-0.2.2-win-x64.zip -Algorithm SHA256` и сравните хеш целиком.
2. Распакуйте ZIP **полностью**, сохранив файлы рядом. Запустите `DiskBurrow.exe` обычным пользователем. Нужны Windows 10 22H2 либо Windows 11 x64. .NET 10.0.12 и SQLite включены. Дополнительный быстрый NTFS-скан запрашивает UAC для отдельного процесса, который только читает метаданные диска.
3. По умолчанию интерфейс русский; English выбирается в Настройках. Закрытие окна прячет его в трей. **Выход** в трее отменяет работу, ждёт завершения и останавливает мониторинг. Второй запуск активирует первый экземпляр текущего пользователя.

Сборка **не подписана**. Windows может показать предупреждение неизвестного издателя/SmartScreen. Изучите исходники и хеш перед запуском. Хеш проверяет целостность, но не является подписью издателя.

Светлая и тёмная темы переключаются сразу в Настройках. Сохранение запоминает выбор для следующего запуска; числовые пороги сохраняют точные значения в байтах.

## Мониторинг и данные

- Системный том определяет Windows. Другие локальные диски/папки выбираются вручную; сетевые диски не проверяются в фоне.
- Полный обход — раз в **6 часов**, первый — через **5 минут** после запуска. Доступны 1, 6, 12 и 24 часа. Свободное место проверяется каждые 5 минут: предупреждение ниже **15 ГБ**. Порог роста папки — **5 ГБ**, повтор не чаще раза в сутки. Пропущенные проверки объединяются, параллельных обходов нет. На батарее полный фоновый обход откладывается по умолчанию.
- Размеры и редактируемые пороги указаны в десятичных **ГБ** (**1 ГБ = 1 000 000 000 байт**). Существующие настройки сохраняют точные пороги в байтах: прежние 15 ГиБ / 5 ГиБ отображаются как 16,10612736 ГБ / 5,36870912 ГБ. Сохранение без редактирования не меняет пороги. JSON-экспорт сохраняет точное число байтов.
- Автозапуск выключен до явного включения и сохранения. При переносе включённой установки проверьте и сохраните настройку нового расположения. Пауза останавливает полные фоновые обходы; проверки свободного места и предупреждения продолжаются; Выход завершает приложение.
- История хранит последние **30** завершённых проверок и до **100** крупнейших файлов на проверку. База SQLite, служебные файлы и логи ограничены **250 МиБ**, логи — **10 МиБ**. При сбое хранения текущий результат остаётся доступен. Данные и настройки находятся в `%LOCALAPPDATA%\DiskBurrow`, вне папки EXE. Перед резервной копией/удалением данных выйдите из приложения. История не входит в ZIP; удаление ZIP не стирает её.
- Журнал очистки хранит локально проверенные пути файлов, сведения о правилах и исходы в пределах того же бюджета. Старые записи только с GUID явно не имеют сопоставления пути; пути не выдумываются.
- Телеметрии и фоновых сетевых запросов нет. Ссылки GitHub/Releases и инструкции программ открываются только по нажатию. Экспорт JSON содержит настоящие пути и требует отдельного подтверждения: проверьте раскрытие данных и место сохранения перед отправкой кому-либо.

## Правила очистки

**Удаление безвозвратно: без Корзины и отмены.** Сначала Анализ, затем проверка путей, возраста и причины, выбор конкретных файлов и подтверждение. Изначально ничего не выбрано. Исключайте файлы/категории в preview либо абсолютные пути в Настройках. Фильтр сохраняет выбранные скрытые строки: они учитываются в итогах выбора. После изменения исключений повторите анализ. Изменившиеся, занятые, непроверенные и запрещённые кандидаты пропускаются; частичные результаты остаются видны.

- Пользовательский TEMP: файлы строго старше **7 суток** в проверенном узком корне. Перенаправленный TEMP не считается безопасным автоматически; пользовательский корень должен пройти проверку в Настройках.
- Пользовательские `CrashDumps`: только `.dmp` строго старше **7 суток**.
- Chrome/Edge: только HTTP `Cache` / `Cache_Data` при закрытом соответствующем браузере. Невозможность проверить состояние блокирует правило. Cookies, пароли, история, service workers и загрузки не являются целями. Для этих кэшей порога возраста нет.
- Reparse points и облачные placeholders пропускаются без загрузки содержимого. Физический размер hard links не начисляется дважды; логические размеры путей могут повторяться. Очистка может удалить явно выбранный путь hard link после обычной повторной проверки; другие ссылки сохраняются, поэтому место может не освободиться. Недоступные/изменившиеся записи делают покрытие неполным и физические итоги неизвестными. Логический размер, известный выделенный объём и занятое место Windows — разные показатели. Завершённый обход не означает полного покрытия тома.

Рекомендации NuGet/pip ведут к штатным инструментам программ: DiskBurrow не запускает их и не удаляет эти кэши автоматически. Таблицы Largest показывают до 1 000 папок и 100 крупнейших файлов, Cleanup — до 2 000 кандидатов; обрезание показано явно. Карта использует отдельный полный живой индекс наблюдённых файлов. История и JSON-экспорт снимков сохраняют прежний ограниченный список файлов.

## Карта диска и быстрый NTFS-скан

Карта показывает вложенные папки и файлы: площадь соответствует размеру, цвет — типу файла. Есть переход внутрь папки, хлебные крошки, назад/вперёд/вверх, масштаб колесом или клавиатурой, фильтр имён с подсветкой или изоляцией. Можно выбрать локальный том и посмотреть занятое/свободное место. Исторические снимки без полного живого индекса явно ограничены.

Быстрый режим запускается вручную для целого локального NTFS-тома. Согласие UAC запускает отдельный процесс чтения MFT; фоновые проверки и удаление остаются в обычном пользовательском процессе. Отмена UAC отменяет запрос. Неподдерживаемый формат или повреждённые метаданные дают ошибку; для отдельной папки или другой файловой системы используйте обычный скан. MFT работающего тома не является атомарным снимком и может отставать от недавних изменений. Перед удалением всегда нужен новый native preview.

Процесс UAC должен работать от той же учётной записи Windows. Ввод данных другого администратора не поддерживается: сканирование завершится отказом. Парсер и канал связи ограничивают число записей, объём передаваемых данных и оценку памяти метаданных; очень большой том может потребовать обычного скана. Физические размеры MFT включают именованные потоки данных; обычный скан измеряет основной поток, поэтому итоги могут различаться.

## Удаление выбранных папок и файлов

Отметьте папки/файлы в Largest или на карте, затем проверьте точные корни, число вложенных файлов/папок, объём данных и предупреждения. Выбор родителя включает потомков один раз. Безвозвратное удаление требует отдельного подтверждения; отмена оставляет файлы на месте. Смена выбора, корня или снимка сбрасывает preview.

Это отдельная ручная операция; четыре правила очистки кешей сохраняются. Корни томов, системные папки, широкие контейнеры пользователя и собственные файлы/данные приложения защищены. Неизвестные защищённые границы, недоступные записи, ссылки и облачные placeholders блокируют полный план удаления. Изменившиеся, занятые и новые записи сохраняются; результат и локальный журнал включают частичные ошибки и отмену. Удаление не получает права администратора от процесса сканирования.

Алгоритм карты и NTFS-парсер адаптированы из [disktree](https://github.com/tobi/disktree), MIT. [Полная атрибуция и лицензия](THIRD_PARTY_NOTICES.txt) включены в portable ZIP.

## Восстановление повреждённой истории

1. Нажмите **Выход** в трее и дождитесь остановки DiskBurrow. Сохраните копию `%LOCALAPPDATA%\DiskBurrow` вне этого каталога, желательно на другом диске со свободным местом, перед изменением файлов.
2. В этом каталоге переименуйте только `history.db` (например, в `history.db.corrupt-backup`) и существующие `history.db-journal`, `history.db-wal`, `history.db-shm` с тем же суффиксом резервной копии. Переместите переименованные копии базы и её служебных файлов вместе в сохранённое место вне `%LOCALAPPDATA%\DiskBurrow` до перезапуска: все оставшиеся файлы каталога данных входят в бюджет хранения. Не удаляйте их и не переименовывайте посторонние файлы.
3. Оставьте `settings.json` и резервные копии настроек без изменений. Запустите DiskBurrow: новая база истории появится при следующей завершённой проверке или записи журнала очистки. Старая история автоматически не восстанавливается; сохраните копию для диагностики.

## Сборка и проверка

На Windows x64 нужны .NET SDK 10 (минимум 10.0.100; `global.json` допускает новые feature bands 10.0) и PowerShell 7:

```powershell
dotnet restore DiskBurrow.slnx --locked-mode
dotnet build DiskBurrow.slnx -c Release --no-restore
dotnet test tests/DiskBurrow.Tests -c Release --no-restore
./scripts/publish.ps1 -Version 0.2.2 -OutputDirectory ./artifacts/release-0.2.2
```

Каталог выпуска должен быть **новым**: скрипт не удаляет и не переиспользует существующий. Зависимости восстанавливаются в locked mode. Оба runtime закреплены на 10.0.12; ZIP self-contained win-x64 содержит только manifest публикации MSBuild плюс лицензию, атрибуцию сторонних компонентов, инструкцию и manifest пакета. PDB, история, отчёты и тесты не поставляются. Байты пакета проверяются на локальные пути. Package-тесты создают отдельный пакет в игнорируемом `work/`, проверяют точный состав, checksum и приватность. При первой сборке нужен интернет для runtime packs; обычная работа приложения его не требует.

Windows CI повторяет locked restore, Release build/tests и упаковку. Для ветки загружает artifacts, для version-tag добавляет ZIP/checksum к Release. Статус проверки каждого выпуска указан с его версией в доказательствах. [Доказательства и ручные проверки](docs/verification.md) отделяют программную проверку WPF/SQLite от вида интерфейса, кликов трея/диалогов, реального завершения Windows и кнопок очистки/автозапуска. Обычный Выход ждёт завершения; принудительная остановка ОС после ограниченного ожидания может помешать последней записи журнала. Destructive-проверки допустимы только на собственных фикстурах.
