# DiskBurrow — проект Windows-приложения

Дата: 2026-10-05. Статус: согласован пользователем; уточнение покрытия включено в план реализации для проверки.
DiskBurrow — предложенное рабочее название; репозиторий ещё не создан.

## Цель и согласованные пожелания

Пользователь устал от повторного заполнения системного диска C:. Приложение должно находить крупные потребители места, показывать рост между проверками, помогать очищать конкретные временные файлы и кэши и предупреждать о повторении проблемы. Выбран вариант с работой в трее и периодическими проверками. Пользователь также поручил выложить проект на GitHub.

Результат: пользователь видит, куда ушло место, что выросло и какие конкретные файлы можно удалить. Фоновые проверки не требуют постоянного внимания. Удаление происходит после просмотра списка и подтверждения в приложении.

Согласованные решения: название DiskBurrow, публичный репозиторий, лицензия MIT, русский и английский интерфейсы, Windows 10 22H2 / Windows 11 x64, portable ZIP как способ распространения.

## Выбор реализации

- Рекомендуется C# / .NET 10 / WPF. Это Windows-приложение с нативным треем через NotifyIcon, фоновыми задачами и доступом к необходимым Win32 API. .NET SDK 10.0.100 доступен локально. Сборка будет self-contained, чтобы пользователю не требовалось устанавливать .NET отдельно.
- WinUI 3 подходит для более современного интерфейса, но добавляет особенности упаковки и развёртывания; для этой задачи преимуществ недостаточно.
- Electron подходит для веб-интерфейса, но добавляет отдельный браузерный runtime к постоянно работающему приложению. Для этого проекта выбираем WPF.

## Поведение приложения

### Окно и трей

Главное окно содержит обзор дисков и свободного места, результаты последней проверки, самые крупные папки и файлы, изменения с предыдущей проверки, очистку и настройки. Русский язык выбран по умолчанию; английский можно включить в настройках. Технические ошибки переводятся в понятные сообщения, подробности доступны отдельно.

По умолчанию отслеживается системный диск, определяемый Windows, а не жёстко заданная буква C:. Другой локальный диск можно выбрать вручную. Сетевые диски не сканируются в фоне.

Закрытие окна скрывает его в трей. Меню трея: открыть, проверить сейчас, приостановить фоновые проверки, выйти. Один экземпляр приложения на пользователя; повторный запуск открывает существующее окно. При завершении Windows приложение отменяет работу и сохраняет только завершённые результаты.

Автозапуск выключен до явного включения пользователем. Portable-сборка регистрирует точный путь своего EXE в HKCU Run; настройка умеет удалить только свою запись. При переносе EXE интерфейс предлагает обновить путь. Разработка и тестирование не включают автозапуск на компьютере мастера.

### Фоновая работа

Полная проверка выполняется каждые 6 часов при работающем приложении. После запуска первая фоновая проверка ждёт 5 минут; вручную начать её можно сразу. Проверки не запускаются параллельно. Пользователь может отменить проверку и приостановить расписание. В настройках доступны интервалы 1, 6, 12 и 24 часа.

Свободное место проверяется каждые 5 минут без обхода файлов. По умолчанию предупреждение появляется при свободном месте ниже 15 ГБ, а предупреждение о росте — при увеличении папки минимум на 5 ГБ между завершёнными полными проверками. Пороги настраиваются. По одному событию приходит одно уведомление; повторное возможно после восстановления состояния или нового значимого изменения. Уведомления о росте не повторяются чаще одного раза в сутки для одной папки.

При работе ноутбука от батареи полные фоновые проверки откладываются, если пользователь не разрешил их. После сна или выключения пропущенные проверки объединяются в одну. Уведомления кликабельны и открывают соответствующий результат; поддержка этого поведения проверяется в реальном Windows-сеансе.

### Сканирование и размеры

Обход работает в фоне, сообщает прогресс без выдуманного процента, поддерживает отмену и продолжает работу после отказа в доступе. Ограничены число одновременно открытых файлов и частота обновления интерфейса. Администраторские права для обычной работы не требуются; недоступные области отмечаются как непроверенные.

Показываются отдельно размер данных и известный размер, занятый на диске. Учитываются идентификатор тома и идентификатор файла, чтобы физическое место hard links не суммировалось повторно. Для родительских агрегатов физический вклад относится к одной канонической записи; интерфейс объясняет особенности ссылок и невозможность гарантировать освобождение этого объёма удалением одной ссылки.

Junction, symbolic links и другие reparse points не обходятся. Приложение не вызывает скачивание облачных placeholders ради подсчёта размера. Пропущенные ссылки, облачные записи и отказ в доступе отображаются в сводке покрытия. Размер занятого тома берётся из Windows и не подменяется суммой доступных файлов: системные метаданные и недоступные файлы могут оставлять разницу.

Если файл меняется во время проверки, результат помечается как приблизительный. Результат обхода — наблюдение за интервал, а не атомарный снимок диска. Незавершённые и отменённые проверки не становятся основой уведомлений о росте. У завершённых обходов покрытие учитывается отдельно для каждого поддерева: неполно проверенные области не используются для уведомлений и вывода об удалении; полностью проверенные области сравниваются, даже если другая часть диска недоступна. Обычный обход каталогов выбран для первого выпуска; чтение MFT не является условием выпуска и не обещается.

### История

Локальная SQLite-база в LocalAppData/DiskBurrow хранит завершённые агрегаты по папкам, до 100 крупнейших файлов каждой проверки, метаданные покрытия и журнал очистки. Содержимое файлов не читается и не сохраняется. Пути остаются локальными.

Хранятся последние 30 завершённых проверок. Совокупный бюджет базы, служебных файлов SQLite и логов — 250 МиБ. Старые данные удаляются, выполняется обслуживание базы; если бюджет нельзя соблюсти, запись новой истории приостанавливается с сообщением, а проверка и просмотр продолжают работать. Логи ограничены 10 МиБ и включены в общий бюджет. Разреженная история и неполное покрытие подписываются явно.

Для каждого завершённого результата можно посмотреть предыдущую проверку и её время. Исчезнувшая папка отображается как удалённая, новая — как новая; недоступную папку нельзя объявлять удалённой. Экспорт локального отчёта выполняется только по кнопке пользователя и предупреждает, что отчёт содержит пути.

## Очистка

### Каталог правил

Первый выпуск включает три семейства конкретных правил:

1. Пользовательский каталог временных файлов, разрешённый системой: файлы старше 7 суток. Если TEMP указывает на корень тома, профиль пользователя, каталог Windows или другую опасно широкую область, правило недоступно. Разрешается только явно проверенная узкая временная область.
2. Пользовательские crash dumps в LocalAppData/CrashDumps: файлы .dmp старше 7 суток. Интерфейс сообщает, что они могут пригодиться для диагностики падений.
3. Известные каталоги HTTP-кэша Chrome и Edge для обнаруженных локальных профилей: только Cache/Cache_Data. Очистка предлагается после закрытия соответствующего браузера. Cookies, Login Data, History, расширения, настройки и сохранения не являются кандидатами.

Для системного мусора интерфейс открывает встроенные настройки памяти Windows и объясняет доступные штатные действия. Приложение не удаляет вручную содержимое WinSxS, Installer, DriverStore, Windows Update и точки восстановления. Пользовательские библиотеки и проекты можно открыть из результатов сканирования, но они не становятся автоматически «мусором».

Для других крупных кэшей предусмотрены понятные рекомендации: название программы, обнаруженный путь и переход к её настройкам или инструкции. Перенос выполняется только способом, поддерживаемым конкретной программой. Автоматического переноса всего AppData через junction нет.

### Предварительный просмотр и выполнение

Кнопка анализа очистки строит план: правило, точный файл, размер, время изменения и причина включения. Категории и файлы можно исключить; ничего не выбрано для удаления до решения пользователя. Настройки позволяют исключить отдельные пути из последующих предложений.

Перед выполнением план проверяется заново: путь находится в разрешённом корне, ни один компонент не стал reparse point, файл имеет прежний идентификатор, размер и время изменения, соответствует правилу возраста, приложение-владелец не работает. Если проверка не пройдена, файл пропускается с причиной.

Исполнитель использует Win32 file handles: открытие с проверкой ссылки и идентификатора и удаление той же проверенной записи по handle. Проверки родителей и допустимой конечной области выполняются при открытом handle. Строковой проверки StartsWith и рекурсивного удаления произвольного каталога недостаточно. Ошибка доступа, блокировка или гонка приводят к пропуску, а не к повторной попытке с повышением прав.

Удаляются только выбранные файлы; рекурсивного удаления корней правил нет. Очистка постоянная, что явно написано перед подтверждением. Универсального отката не обещаем: создание копии каждого кэша на заполненном диске противоречит задаче. Закрытый файл, удалённый другим процессом, учитывается отдельно от успешно удалённого.

После операции показаны удалённые и пропущенные файлы, ошибки и изменение свободного места. Сумма размеров кандидатов не называется гарантированно освобождаемым объёмом; hard links, открытые handles и параллельная запись могут изменить результат. Журнал локальный и подчиняется бюджету хранения.

## Границы компонентов

- DiskBurrow.Core: модели снимков, правила сравнения, пороги уведомлений, политики очистки и интерфейсы хранилища/файловой системы. Не зависит от WPF.
- DiskBurrow.Windows: Win32-адаптеры обхода, идентичности и размера файлов, проверки ссылок, исполнения очистки, питания, свободного места и автозапуска.
- DiskBurrow.Storage: SQLite-снимки, настройки, миграции схемы, лимиты хранения и журнал.
- DiskBurrow.App: WPF-окно, навигация, модели представления, трей, расписание, локализация и уведомления.
- DiskBurrow.Tests: проверки политик и интеграционные испытания на изолированных временных каталогах.

Приложение не требует службы Windows, не отправляет телеметрию и не обращается в сеть во время обычной работы. Ссылки на GitHub и справку открываются только по действию пользователя. Сканирование и удаление используют раздельные интерфейсы и отдельные пользовательские действия.

## GitHub и доставка

После согласования проекта и реализации: локальный Git-репозиторий, публичный GitHub-репозиторий DiskBurrow в аккаунте пользователя, исходники, MIT LICENSE, README на английском с русской версией, инструкции сборки и предупреждения о необратимости очистки. Если имя занято или авторизация не доступна, нужны выбор другого имени или вход пользователя; секреты не запрашиваются и не сохраняются в проекте.

GitHub Actions на Windows выполняет restore, Release build и тесты, затем публикует self-contained win-x64 ZIP с SHA-256. Выпуск содержит приложение и файлы поставки, но не локальную историю, отчёты сканирования, дампы, тестовые данные, пользовательские пути, ключи или токены. Автоматическое скачивание и установка обновлений не входят в проект; в интерфейсе есть ссылка на Releases.

Иконка трея и приложения — собственный простой графический знак без чужих торговых марок. Проверка подписанных файлов не обещается: для подписи нужен отдельно предоставленный сертификат. Первый GitHub Release создаётся после проверки фактической portable-сборки.

## Проверка результата и критерии готовности

1. Unit-тесты: рост/уменьшение, пороги и подавление повторных уведомлений, неполные результаты, исчезнувшие папки, исключения, возраст кандидатов и границы разрешённых областей.
2. Windows-интеграция в временном дереве: пустые и длинные пути, junction cycle, hard links, заблокированные файлы, изменение между preview и execute, подмена ссылкой, отмена и недоступные каталоги. Проверки удаления никогда не используют реальный пользовательский TEMP или браузерные данные.
3. История: перезапуск, повреждённая запись, миграция, ограничение количества снимков и бюджета базы с WAL/логами, нехватка места на сохранение. Ошибка истории не должна приводить к очистке или зависанию сканирования.
4. Реальный Windows-запуск собранного приложения: окно, меню трея, скрытие/возврат, второй экземпляр, отзывчивость при проверке, отмена, настройки, обе локализации, уведомление и переход по нему. GUI-сценарии, недоступные для текущей автоматизации, отмечаются как непроверенные, а не как пройденные.
5. Проверка реального C: только в режиме чтения: покрытие, размеры и сопоставление свободного места с Windows. Никакой фактической очистки пользовательских данных при разработке без отдельного прямого поручения.
6. Проверка portable ZIP из отдельного каталога: запускается без установленного Desktop Runtime, создаёт данные в LocalAppData, корректно завершает фоновые задачи, содержит только ожидаемые файлы.
7. Перед публикацией: тесты и Release build проходят; README соответствует фактическому поведению; CI и пакеты доступны в GitHub; известные ограничения честно указаны. Публикация исходников и выпуска авторизована пользователем в разговоре.
